# Docker: откат релиза по healthcheck

## Цель

В локальной лаборатории собрать два автономных `scratch`-образа без загрузки базового образа. Первый отвечает `200` и `stable-v1`; второй служит неисправным кандидатом и отвечает `503`. После отказа кандидат удаляется, а исходный image ID восстанавливается на том же loopback-порту.

## Требования

- Linux Docker Engine на локальном Unix socket и права на работу с ним.
- Bash, C-компилятор со static libc, `tar`, `curl` и Docker CLI.
- Явное подтверждение лаборатории через `ATLAS_DOCKER_PROJECT=1`.

Контексты с TCP/SSH endpoint и переменные `DOCKER_HOST`/`DOCKER_CONTEXT` отклоняются; после проверки все команды закреплены за проверенным Unix endpoint. Образы создаются локально из статического бинарного файла, загрузки образов нет. Engine публикует dynamic port на отдельном bridge; binding ограничен `127.0.0.1`. На проверенном Engine режим `--internal` несовместим с публикацией порта, поэтому bridge сохраняет egress. Приложение не открывает исходящих соединений; не подключайте к лабораторной сети другие контейнеры. Контейнеры работают без root, с read-only rootfs, без capabilities, с `no-new-privileges` и ограничениями ресурсов. Эти меры ограничивают учебный процесс, но не превращают доступ к Docker Engine в изолированную sandbox: запускайте только проверенный код на выделенном локальном Engine.

## Запуск

Из корня репозитория:

```sh
ATLAS_DOCKER_PROJECT=1 bash academy/projects/docker/capstone.sh
```

Скрипт сообщает три результата: начальный `stable-v1` здоров, `candidate-v2` получает `unhealthy` и `503`, прежний image ID вновь отвечает на том же локальном порту. Все созданные образы, контейнеры и сеть имеют уникальные метки одной лаборатории. При выходе скрипт удаляет только ресурсы с этой меткой; глобальные очистки не используются.

## Разбор результата

Зафиксируйте image ID исходного релиза, HTTP-ответ кандидата и image ID после восстановления. Объясните, почему `running` не равен `healthy`, чем healthcheck отличается от маршрутизатора трафика и как убедиться, что откат вернул прежний артефакт.

Упражнение моделирует health-gated решение и замену контейнера с коротким перерывом. Оно не проверяет переключение ingress, zero-downtime, постоянные данные, backup или готовность к production.
